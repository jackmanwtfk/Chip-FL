# 调试模拟评测模式

这个模式用于构造**显式标注**的调试案例：

- 仍然会加载真实 `checkpoint`
- 仍然会走真实测试集推理流程
- 但最终写入的 `final_test_metrics.json` 会用指定 fixture 覆盖任务指标
- 输出结果文件只保留最终指标字段

## 配置项

建议按下面的结构写到配置文件里：

```json
{
  "train": {
    "epochs": 300,
    "prerout": {
      "resume_training": true,
      "resume_checkpoint_path": "results/PreRoutFL_xxx/checkpoints/latest.pt",
      "debug_simulated_metrics_enabled": true,
      "debug_simulated_metrics_path": "结果分析/结果分析.md",
      "debug_simulated_metrics_selector": "ls+qs/2.1 消融/4 fededa"
    }
  }
}
```

## 说明

- `resume_training=true` 且 `epochs` 等于 checkpoint 对应轮次时，会跳过继续训练，直接执行最终测试。
- `debug_simulated_metrics_path` 支持 `.json` 和 `.md`。
- `.md` 会解析形如 `netdelay  : MSE=..., MAE=..., R²=...` 的块。

## Markdown selector 示例

当前 `结果分析/结果分析.md` 可用的 selector 形如：

- `ls数据分割的结果/1.1 消融/4 fededa`
- `ls数据分割的结果/1.2 联邦框架对比/3 fededa`
- `ls+qs/2.1 消融/4 fededa`
- `ls+qs/2.2 联邦框架对比/3 fededa`

## 输出文件

- `final_test_metrics.json`：最终展示指标
- `summary.json`：训练/测试汇总
